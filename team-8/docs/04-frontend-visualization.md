# Spec 4. 프론트엔드 데이터 시각화 및 UI 구현

## 목표
백엔드가 반환한 실제 급식 데이터를 React UI로 보기 좋게 표시한다.

## 선행
Spec 2-A(호출 로직), Spec 3(실제 데이터). 응답 구조는 [api-contract.md](api-contract.md).

## 표시 정보와 순서
1. 날짜(+ 이전/다음 날 이동)
2. 끼니별 카드(조식 → 중식 → 석식)
3. 카드 내용: 끼니명, 메뉴 목록, 칼로리

데이터가 "끼니 3개 × 메뉴 목록" 구조라 **카드 + 목록**이 적합하다(기존 시안의 `home-meal-card`와 동일).

## 컴포넌트
```text
MealView            날짜 상태, fetch 호출, loading/error/data 분기
├─ DateNav          이전/다음 날, 날짜 선택
├─ MealCard         끼니 하나 (type, menu, calories)
├─ LoadingState     로딩 표시
├─ ErrorState       오류 메시지 + 다시 시도 버튼
└─ EmptyState       "이 날은 급식이 없어요"
```

## 작업
1. `meals` 응답을 `useState`에 저장하고 날짜 변경 시 `useEffect`로 재조회
2. `data.meals.map`으로 `MealCard` 렌더링(`key`는 `type`)
3. 상태별 화면 처리

   | 상태 | 화면 |
   |------|------|
   | loading | 스켈레톤 또는 "불러오는 중…" |
   | error | 메시지 + 다시 시도 |
   | `meals: []` | 급식 없음 안내 |
   | 정상 | 카드 목록 |
4. 기존 `style.css`의 급식 스타일 재사용, 모바일 폭에서도 카드가 세로로 쌓이게 확인
5. Spec 1에서 넣은 임시 예시 데이터와 "예시 식단" 문구 제거
6. 실제 응답으로 레이아웃·스타일 다듬기

## 완료 조건
- [ ] 평일 날짜에서 조식/중식/석식 카드가 실제 메뉴로 표시된다
- [ ] 주말 날짜에서 빈 상태 안내가 표시된다
- [ ] 백엔드를 끄면 오류 화면과 다시 시도 버튼이 표시된다
- [ ] 로딩 중 표시가 보이고, 빠르게 날짜를 바꿔도 이전 응답이 덮어쓰지 않는다(요청 취소 또는 최신 요청만 반영)
- [ ] 모바일 폭(약 375px)에서 레이아웃이 깨지지 않는다
- [ ] 하드코딩된 예시 데이터가 남아 있지 않다
