# API 계약 (프론트 ↔ 백엔드)

> 초안. Spec 2-A/2-B 시작 전에 팀이 확정한다. 변경 시 02a, 02b, 03, 04를 함께 수정.

## GET /api/meals

학교 급식 조회.

| 항목 | 값 |
|------|----|
| Query `date` | 선택. `YYYY-MM-DD`. 없으면 서울 시간 기준 오늘 |
| 성공 | `200 OK`, `application/json` |
| 급식 없음 | `200 OK`, `meals: []` (오류 아님) |
| 잘못된 date | `400`, `{ "message": "..." }` |
| 외부 API 실패 | `502`, `{ "message": "..." }` |

### 응답 형식 (최종, Spec 3 이후)

```json
{
  "date": "2026-11-09",
  "school": "경북소프트웨어마이스터고등학교",
  "meals": [
    {
      "type": "중식",
      "menu": ["잡곡밥", "된장찌개", "배추김치"],
      "calories": "842.3 Kcal"
    }
  ]
}
```

- `type`: 조식 / 중식 / 석식
- `menu`: 메뉴 이름 배열. NEIS의 `DDISH_NM`에서 `<br/>` 분리, 알레르기 번호 `(1.2.5)` 제거
- `calories`: NEIS `CAL_INFO` 그대로(문자열)

### 고정 응답 (Spec 2-B 단계)

위와 같은 형식으로 하드코딩한 값을 반환한다. 이렇게 하면 3단계에서 데이터 출처만 바뀌고 프론트는 수정이 필요 없다.

## 오류 응답 공통 형식

```json
{ "message": "사용자에게 보여줄 수 있는 설명" }
```

외부 API 키·URL 등 내부 정보는 포함하지 않는다.

## 연결 방식

- 개발 중 프론트는 상대 경로(`/api/meals`)로 호출하고 Vite proxy가 `localhost:8080`으로 전달한다. (CORS 설정 불필요)
